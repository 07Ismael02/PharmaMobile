La regla real del backend para un segundo DELETE se verificó en `ProductoServiceImpl`: si ya está inactivo lanza `ReglaNegocioException`, mapeada a 409. No se cambia el contrato solo para coincidir con el ejemplo 404 del PDF. La demostración de un 500 o de JSON inesperado aparece en las diapositivas de clase, **no** sustituye ninguno de los ocho escenarios del PDF principal.
